Security and RLS findings

  • Service-role exposure: source uses a server-side admin client in allowlisted *.server.ts modules. No SUPABASE_SERVICE_ROLE_KEY or service_role string was found in the built public client assets. This static scan does not replace a runtime/API security test.
  • Public catalogue path: the public storefront loader calls the get_public_store RPC through the anon client. Tenant isolation and unpublished store behavior remain unverified against Supabase.
  • Documentation correction: SECURITY.md previously claimed service-role access was restricted to exactly five files. The current ESLint allowlist is broader; the description now reflects the actual categories and authorization requirement.
  • RLS verification: NOT RUN. No staging access token or isolated merchant identities were available. Production was not queried or modified.

Fixes applied during this audit

  • Playwright now rejects non-local base URLs and launches the built Nitro Node server.
  • Added role-aware merchant A/B, customer A/B, and guest fixtures. Missing role credentials skip setup rather than reading stale auth-state files.
  • Moved storefront launch checklist links to their typed internal route targets.
  • Offline POS stock deduction now skips service-only sale lines that have no product ID.
  • Public service and Paynow availability lookup errors are surfaced instead of being silently converted into empty or default data.
  • Corrected the service-role allowlist description in SECURITY.md.
